2. Architecture

L’application suit une architecture en trois niveaux.

ClientReact dans le navigateur
→
ServeurAPI REST Django / DRF
→
DonnéesBase relationnelle et stockage des documents

Archivage d’un dossier

  1. L’utilisateur authentifié ouvre le formulaire d’enregistrement.
  2. Le frontend envoie le dossier et le fichier à l’API, avec le jeton dans l’en-tête.
  3. Le backend vérifie le jeton et les droits, puis valide les données.
  4. Le fichier est stocké ; les métadonnées et une entrée de journal sont écrites en base.
  5. Le backend confirme, le frontend affiche le succès.

Le choix de Django s’appuie sur son ORM, son administration intégrée et ses protections par défaut (CSRF, sessions, hachage des mots de passe). React permet une interface en composants réutilisables.

5. API et interfaces

API REST au format JSON, routes préfixées par /api/. Hors connexion, chaque requête exige un jeton JWT dans l’en-tête Authorization: Bearer …. Le jeton a une durée limitée et doit être renouvelé.

MéthodeRouteRôle
POST/api/auth/login/Tous (obtention du jeton)
GET/api/dossiers/Personnel médical, administratif
POST/api/dossiers/Personnel administratif
GET/api/dossiers/{id}/Selon rôle
POST/api/dossiers/{id}/documents/Personnel administratif
GET/api/utilisateurs/Administrateur

Les échanges avec l’extérieur se font aujourd’hui en PDF. HL7, FHIR et DICOM sont une évolution possible (section 12).

6. Sécurité

Authentification par identifiant et mot de passe (mots de passe hachés par Django), puis jeton à durée limitée. Les droits suivent un modèle par rôles (RBAC).

RôlePermissions proposition à confirmer
AdministrateurAccès complet, gestion des comptes et de la configuration
Personnel médicalLecture et écriture sur les dossiers
Personnel administratifLecture et écriture sur dossiers et documents
AuditeurLecture seule du journal d’accès
  • Chiffrement en transit : HTTPS obligatoire. Au repos : à confirmer
  • Journalisation : chaque consultation, création ou modification est enregistrée (utilisateur, action, horodatage).
  • Secrets : jamais dans le code ni la documentation ; variables d’environnement uniquement.

7. Conformité

Le traitement des dossiers respecte le cadre applicable à la protection des données de santé et au secret médical. Trois points restent à fixer avec la direction de l’HDD : cadre réglementaire durée de conservation procédure des droits d’accès et de rectification. Le journal d’accès sert de base aux audits.

8. Installation et déploiement

Prérequis pressentis à confirmer : Python 3 et pip, Node.js et npm, PostgreSQL, Git.

git clone https://github.com/yannjeffs/tutore_vrai.git
# Backend
python -m venv venv && source venv/bin/activate
pip install -r requirements/development.txt
python manage.py migrate
python manage.py runserver
# Frontend
npm install
npm start    # ou npm run dev (projet Vite)

Configurer d’abord les variables d’environnement (base de données, clé secrète Django, jeton). En production : serveur web (par exemple Nginx devant Gunicorn), build de production du frontend et HTTPS.

9. Exploitation

  • Supervision : surveiller régulièrement les journaux applicatifs (erreurs, accès).
  • Sauvegarde : sauvegardes régulières de la base et du stockage des documents, avec test périodique de restauration.
  • Mises à jour : branche dédiée, tests, déploiement après validation.
  • Continuité : plan de reprise pour garantir l’accès aux dossiers en cas de panne.
